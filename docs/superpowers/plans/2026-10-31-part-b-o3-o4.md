## Task 4: G4 - rerun after repair replays retained upstream submissions [sensitive: ordering, money; mx-adversary]

**Files:** new `src/deploy_workflow/replay.py`; edit O2's `run_pathway.py` (and O5's loop only through its public interface); new `tests/test_owner_replay.py`.

**Why a fresh run:** `Execution.begin` refuses a settled input set and a second repair (`execution.py:657-669`), `invalidate`
re-stales downstream heads (`execution.py:308-326`), and the pack hash and every `OwnerBinding` include `run_id` (`contracts.py:82-95`; ow:580-591), so a retained submission cannot be re-bound into the old run. No `execution.py` change is needed or made.

**Behaviour:**
- `plan_replay(earlier: Path, plan, repaired: frozenset[str]) -> ReplayPlan`: `live = repaired | downstream(repaired)` (modules that, transitively, consume a repaired module, from the registry graph); every other **analytical** module is replayed; deterministic modules (CP-MODEL) are never replayed: `publish()` runs again (O1). The earlier run must hold a valid, settled attempt for each replayed module (else the module goes live and the plan reports why; never a silent gap).
- `replay_module(workflow, earlier, module_id)`: reads the earlier `Execution(earlier)` snapshot (read only; the test hashes the earlier directory tree before and after) and finds the module's settled ticket; for each step of the module in order it takes the earlier **valid** `OwnerSubmission` for `(ticket, step_id)` matched **by module and step, never by invocation digest**; re-issues the earlier epoch's `call_ids` (`OwnerCall.tool`/`arguments`, from `owner-run-audit/calls`) through `workflow.invoke`, calls `workflow.read_inputs()` when the step needs inputs, and submits the retained payload text from `owner-run-audit/payloads/<payload_sha256>` through `workflow.submit_review`. It records a `replays` audit record per step: earlier run id, module, step, earlier payload sha, new payload sha, new `snapshot_sha256`.
- Divergence stops the run, never falls back to a live call: a replayed `invoke` whose body differs from the earlier `OwnerCall.body` raises `ReplayDiverged(module, step, "call")`; a replayed submission that is not `valid` raises `ReplayRejected(module, step, issues)`. `read_inputs` bodies are **not** compared (they may embed the new `run_id`/pack hash; the record carries both hashes); Task 4 Step 0 spikes whether the call bodies are run-independent and, if not, narrows the comparison and reports (Q4). The spike also checks (L5) that a retained payload validates under a new `run_id`; if it does not, the task stops BLOCKED.
- `run_pathway(..., replay_from: Path | None = None, repaired: frozenset[str] = frozenset())` (O2 keyword-only additions, defaults unchanged behaviour): `replay_from` is an earlier **run directory**; it must contain `run.json` or a retained `execution/`, and `repaired` must be non-empty and name planned analytical modules (else refused before anything is written). The new run gets a new `run_id` (the caller's, as today; equal to the earlier one is refused). `run.json.replayed_from_run` is the earlier `run_id`, else `null` (contract :402). The ToolLoop is driven only for live modules; replayed steps send no model request, so `calls.jsonl` holds only the calls the rerun sent, each with `call_index` counted from 0 per `(module, step, attempt)` as O5 defines it; `spent_usd` is the sum of those records; and no replayed record is written.
- Replay precedes live work in plan order: a live module that precedes a replayed one in the plan is begun first (the walk is plan-ordered; the loop switches per module between `replay_module` and `ToolLoop`).

**RED tests** (offline; earlier run produced by a recorded-adapter walk over O1/O2's synthetic preset, recordings authored by the test as O5 Task 7 does):
- [ ] `test_rerun_replays_upstream_and_runs_repaired_live`: earlier run settles `A, B, CP-5`; repair `B` (new recording for `B` only): the rerun has a new `run_id`, `run.json.replayed_from_run == earlier`, `A` replayed (no `calls.jsonl` record with module `A`), `B` live, CP-5 live (downstream), the receipt verifies.
