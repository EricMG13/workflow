**Goal:** Gap G11. Replace the pack-only "resolve CP-0 gaps" CP-DR with independent research that supports CP-1C and CP-2, built to Codex's description (`git show 80748343:work/model-testing/recon/cp-dr-v2.4-codex.md`) read with the user's intended usage and OD1-OD12 (`context-file-consumption.md:543-561`). It is this repo's own version `cp-dr/2026-10-31`, with no claim of work-side v2.4 parity.

**Architecture: one run.** CP-DR is a module of the run, ordered CP-0, CP-1, **CP-DR**, then CP-1C and CP-2.

- *Evidence enters the pack at the start.* The research intake (supplied files and, once the pause lifts, web items from the user's research manifest) runs **before `prepare`**; each retained item is a hashed text source with a reserved id `ev-<n>`. Files published after the run's as-of or the context cutoff are refused before preparation (R4: undated items refused when as-of is before today). The pack is fixed at start, so nothing mutates it (`replace_pack` stales every head, `execution.py:908-931`, and is never used).
- *Anchors are live in the same run.* CP-0 and CP-1 run live; CP-DR's `begin` binds both as required, blocking edges; Python checks issuer, run, period and the CP-0 hash CP-1 consumed.
- *The brief is CP-DR's first owner step* (`brief`), with a source scope that excludes research sources; its second step `research` reads every held source. Python locks the brief (hash) before the `research` step.
- *Consumers get a bound head, not a pack source.* `CONTEXT_PRODUCERS` (`execution.py:227`, bound at `:254-258`) gains `"CP-1C": ("CP-DR",)` and `"CP-2": ("CP-DR",)`: a settled CP-DR head is an `Input` of the consumer, never a registry edge, and `invalidate` (`:308-323`) stales the consumer if CP-DR changes. The "dossier" (Markdown) is rendered by Python from that head; its hash is the head's `result_sha256`.
- *Replacement (OD8).* Same evidence, new dossier version: an O3 rerun with `repaired={CP-DR, CP-1C, CP-2}` (fresh `run_id`, CP-0/CP-1 replayed, which is valid because the pack is unchanged). New evidence: a fresh live run (the pack changes, so CP-0 must re-review).

`run_pathway(cp_dr=True)` (O2; refused with `CpDrNotBuilt` until O7b-1, R6) drives it. With `cp_dr=False` nothing here runs.

**Tech Stack:** Python 3.13, stdlib (`http.client`, `ssl`, `socket`, `ipaddress`, `hashlib`, `json`), pydantic `Contract`, pytest, hypothesis, ruff, mypy strict. No new dependency.

## Global Constraints

- **No stub or fake value standing in for real behaviour.** No placeholder evidence, hash, date, or fabricated "not found". A missing input is a named refusal; missing evidence is `missing` with a limitation, never 0 or N/A.
- **No catch-all that hides a failure.** Every `except` names its exception and re-raises or records a named fault. No fail-open is planned: a failed web fetch is recorded on the item (`fetch_failed`, reason) and logged, the items it would have supplied are simply absent, and questions stay unanswered, never filled.
- **No network in any test.** Web retrieval is a live call and waits for the pause to lift (OD3). The gate is a ruling under `docs/rulings/` with `lifts: live-provider-pause`, `by: user`, `date:` and a `configs:` line naming `web-retrieval` (R2); checked before any DNS lookup. Offline runs use supplied evidence only. Tests inject a resolver and a connector and monkeypatch `socket.socket` to raise.
- **`src/deploy_vii` changes are only B1's O7 list** (`docs/rulings/2026-10-31-context-plan.md:9-14`): `methods/cpdr.md`, registry (`methodology.json`), decision 0007, `execution.py` input binding, `methodology.json` TDR.4-6, `bindings/cpdr.py`. Each: a `post_import_patches` D12 record in `docs/reuse/manifest.json` (fields as the O1 record) and an `mx-adversary` review. Anything else: stop BLOCKED.
- **Untrusted evidence is data.** Evidence text reaches a model in two ways: prompts and **source-tool results** (`search_pack`/`read_pages`, `tools/source.py`). Both wrap research sources in O6's untrusted-evidence fence (R4, O6 rule 5). A body the fence refuses (e.g. it contains the fence terminator) becomes a rejected item. Evidence text never selects a tool, URL or path.
- **Python owns arithmetic and checks**: counts, hashes, dates, cutoff, 1-32, independence, caps.
- **Every commit leaves the suite green** for the files it touches and for every test that pins them (M5): changes that break pinned oracles ship with their re-pin in the same commit.
- **Test command:** `PYTHONPATH=src "/Users/ericguei/Documents/Deploy Workflow/.venv/bin/python" -m pytest <paths> -q`; gates on changed files: `ruff check`, `ruff format --check`, `mypy`; `cases/pins.py --check`; full suite once at hand-off (B3). Each task starts with RED tests; the report quotes each RED failure.
- **Every report ends with `Not verified:`** and lists its **R7 changes** (below).
- **Roles (AGENTS.md independence; B2):** oracle *preparer* = one `mx-feature`; oracle *reviewer* = `mx-precise`, not the preparer; *builder* = another `mx-feature` that prepared and reviewed none of that task's oracles. ## Task O7b-2: R4 web retrieval tool [SENSITIVE: security; mx-adversary]

Reviewed alone. **Files.** New `research/webfetch.py`; wire into intake for manifest items with a `url`; tests `tests/research/test_webfetch.py`. Depends on O7b-1 and O5's live gate.

**Behaviour (M4).** No search endpoint is built: **URLs come only from the user's research manifest** (a discovery endpoint needs a user ruling; cost: no discovery of unlisted sources). `https` only. The connection is an `http.client.HTTPSConnection` subclass whose `connect()` dials the **checked IP** and wraps with `ssl.create_default_context()` and `server_hostname=host` (`check_hostname` and `CERT_REQUIRED` untouched), so there is no second resolution (no DNS rebinding), no `file:`, `ftp:`, `http:` or `data:` handler exists (no `urllib` opener), and proxy variables are never read. Resolution through an injected resolver; **every** address must be public (loopback, private, link-local, multicast, unspecified, reserved, metadata ranges refused; `::ffff:a.b.c.d` unwrapped first). Redirects are followed manually, at most 3, each hop re-checked (scheme `https`, host resolved and public again; a cross-host hop is allowed only to another manifest-listed host, else refused). A connect timeout and a total timeout; the body is read at most `cap + 1` bytes and an item over `cap` is refused and recorded, never truncated. The request carries no run data: the path/query is the manifest URL verbatim. The gate (`LivePauseInForce` unless a ruling with `lifts: live-provider-pause`, `by: user`, `date:`, `configs:` naming `web-retrieval`) is checked before any resolver call.
