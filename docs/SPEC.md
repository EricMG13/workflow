# Tool-assisted module and deliverable checkpoint

## User-approved scope

Create a new, simple project using only relevant Claude code. Establish LEAD,
two coordinators and PR MANAGER. Complete the intended analytical modules using
actual tools, actual downstream consumption and assigned rendered deliverables.
The design follows the user's explicit proceed instruction and established scope.

There are 26 intended owners: 24 analytical plus deterministic CP-MODEL/CP-OS.
Retired CP-MEMO is excluded; its content duties belong to actual deliverables.
CP-3B/CP-6A are distinct intended owners, not extra counts for legacy aliases.

## Completion evidence

Each analytical owner needs an independent applicable positive case and a failure/gap
case; supported tool schema and permitted scope; actual tool arguments/results;
validated/settled artifact and producer/consumer identities; visible section values,
units, dates, citations, limitations and status; relevant checks and independent
review. Review JSON is a legitimate retained submission, not proof of tool use by
itself. Mocks/direct composers are component evidence. Deterministic owners prove
real publication/navigation without artificial model calls.

The six deliverable pathways are credit snapshot, earnings update, relative value,
covenant/refinancing, distressed/restructuring and portfolio decision. Model HTML,
calculation JSON, full analysis, evidence and limitations must agree with the selected
run. Missing implementations may not be disguised as input gaps or placeholder pages.

## Technical decisions delegated by the user

Use a fresh local Git repository named Deploy Workflow. Keep Python 3.13 and the
existing tested arithmetic/validation/render approach. Preserve the imported
`deploy_vii` package name internally; build a small public `deploy_workflow` interface.
These naming/layout decisions are bootstrap choices, not previously stated user names.
Source is pinned by file and commit. No old Git history, private issuer pack,
credentials, old runtime environment or active staged WIP is imported.

## Constraints

Financial/stateful coding and sensitive oracles: GPT-6.1 Sol/high. Fully specified
mechanics: GPT-6 Luna/medium. Small exclusive tasks; independent expected results
first. Preserve all scoped permissions and Python-owned Decimal arithmetic.
Live/paid/provider testing stays paused. One heavy local job, two disjoint lanes.
Confidence review follows code changes; non-trivial changed functions also receive
the user's rewrite-tournament workflow. The bootstrap adds no provider or publication
authority. Internal offline host-agent tool use can qualify with actual invocation
and submission lineage; developer tools used for coding do not count.

## Deferred

Enterprise tenant identity/secrets, production deployment, multi-user operations,
broad host/provider certification, background resource launchers, general durable
B2–B5 infrastructure, optional DR peer appendix, OCR services and workbook export.
Bring forward only a bounded portion that demonstrably unblocks a named module.
