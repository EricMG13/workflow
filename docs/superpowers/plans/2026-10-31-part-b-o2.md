## Task 1: HTML converter and the line rule (R1) [mx-precise]

**Files:** `src/deploy_workflow/html_text.py`, `tests/test_html_text.py`, the measurement note above.

**Why a rule is needed.** `prepare` accepts only text, PDF and XLSX (`preparation.py:29-33`), and
`text_content` makes one span per `str.splitlines()` line with locator `line:N`
(`preparation.py:74-80`; it decodes `utf-8-sig` strictly and refuses NUL, :75-77). A citation must sit
inside one span (`readiness.py:145-172`), so the line rule decides which golden quotes a model can cite.

**Measurement (step 1, before any code).** Run
`PYTHONPATH=src "…/.venv/bin/python" work/context-plan/probes/p4_line_policies.py "$PWD" "/Users/ericguei/Documents/Deploy Workflow/artifacts/public-corpus/v1"`.
Controller's run on 2026-10-31 (843 golden quotes, probe parser, not this converter):

| rule (new line at) | quotes not inside one line |
|---|---|
| R1 as written: p, div, tr, li, br, h1-h6 | 208 |
| no `div` | 107 |
| `tr` and `p` | 105 |
| `tr` only | 76 |
| no line break at all | 27 |

The 27 at "no line break" come from the probe's parser differing from `check.py`'s; this converter
implements `check.py`'s semantics exactly, so its own floor is measured in step 3. The implementer
re-runs the probe, then records in the measurement note, **per rule**: misses, line count, and median,
p99 and maximum line length in characters on the 22 golden HTML sources, and the controller rules the line rule from them before Task 2 (the length ceiling is set with O4's `read_inputs` byte cap) (the probe prints only misses; the length statistics come from a
scratch script in the scratchpad, not committed). Encoding was measured the same day (scratch script,
22 distinct golden HTML files): all strictly valid UTF-8, none with a BOM or NUL, none declaring a
charset in the first 4 KB. The note records this count again.

**Behaviour.**
1. `convert_html(raw: bytes) -> ConvertedHtml` (frozen dataclass `text: str`, `encoding: str`,
   `line_count: int`). Pure; reads no file.
2. Decode: BOM `utf-8-sig`; else strict `utf-8`; else the charset in a `<meta>` or XML declaration within
   the first 4096 bytes looked up with `codecs.lookup` and **only** `utf-8`, `windows-1252`, `iso-8859-1` or `ascii` accepted (any other name raises `UndecodableHtml`, L13), decoded strictly; else raise
   `UndecodableHtml`. Never `errors="replace"` (the probe's choice would turn bad bytes into a
   silent U+FFFD inside a citable line). A NUL in the decoded text raises `UndecodableHtml`
   (`text_content` would refuse it later; refusing here names the source before any write).
3. Visible text follows `check.py`: `SKIP` (script, style, head, `ix:header`) and `display:none`
   elements dropped, `VOID` tags never pushed (`cases/goldens/check.py:72-73, 108-150`), `<body>` ends an
   unclosed head, entities unescaped (`convert_charrefs=True`). Constants are copied into the module
   with a test that compares them with `check.py`'s sets (loaded by `importlib`, test only), because
   `src` must not import from `cases/`.
4. Line rule: a `"\n"` is emitted at the start and end of each tag in `LINE_TAGS` (the chosen rule); every
   other `check.py` `BLOCK` tag emits a space. Each line is whitespace-normalised and zero-width characters
   (U+200B/C/D, U+2060, U+FEFF) deleted exactly as `normalise` does (`check.py:161-163`); because
   `\s` covers `\x0b \x0c \x1c-\x1f \x85    `, no character that `splitlines` would split
   survives inside a line. **Empty lines are dropped** (the earlier review left this to O2): empty spans
   are citable noise and the probe counts without them. Consequence stated in the docstring:
   `line:N` locators number the converted text, not the HTML.
5. Output: lines joined by `"\n"` plus a final `"\n"`; a document with no visible text converts to `""`
   (`text_content` then reports coverage `empty`, and the source is prepared as such, not refused).

**RED tests** (concrete inputs; expected values written in the test, not derived):
- `convert_html(b"<html><body><table><tr><td>Revenue</td><td>1,234</td></tr><tr><td>Cost</td><td>(5)</td></tr></table></body></html>").text == "Revenue 1,234\nCost (5)\n"` (rule `tr`); with `<span>(</span>1,234<span>)</span>` the text is `(1,234)`.
- `<head><title>T</title></head><body>x<script>y</script><style>z</style><div style="display: none">h</div>w</body>` converts to `"x w\n"` for `LINE_TAGS={tr,p}` (no break on `div`, space only).
- `<ix:header>H</ix:header><p>A</p><p>B</p>` gives `"A\nB\n"` (`ix:header` dropped).
- Empty paragraphs: `<p>A</p><p>  ​ </p><p>B</p>` gives `"A\nB\n"`.
- Characters that split lines: `<p>a b\x0bc\x85d</p>` gives `"a b c d\n"` and `len(text.splitlines()) == 1`.
- Encoding: `"<p>café</p>".encode("utf-8")` and `b"\xef\xbb\xbf<p>x</p>"` convert; `b'<meta charset="windows-1252"><p>caf\xe9</p>'` gives `café`, encoding `windows-1252`; `b"<p>caf\xe9</p>"` (no declaration) raises `UndecodableHtml`; `b"<p>a\x00b</p>"` raises `UndecodableHtml`.
- Equivalence with `check.py`: for the six fixture strings above, `" ".join(lines)` normalised equals `check.visible_text(html)`.
- Hypothesis: for any generated nested tags/text, `convert_html(...).text.splitlines()` equals `text.split("\n")[:-1]` (no hidden splits) and no line is empty or has leading or trailing spaces.
- Corpus test (skipped with a named reason when the corpus directory is absent): for the goldens' HTML files, no `UndecodableHtml`; the miss count for the chosen rule equals the number recorded in the measurement note (Task 6 owns the exception list).

**Commands:** the pytest line for `tests/test_html_text.py`; the probe command above.
**Commit:** `feat(workflow): stdlib HTML to line converter with check.py visible-text rules (O2, R1)`

## Task 2: Input checks and the pack root [security: mx-adversary]

Starts after the controller has ruled the line rule from Task 1's note (Q1).

**Files:** `src/deploy_workflow/run_inputs.py`, `tests/test_run_inputs.py`.

**Types.** `CaseSource(source_id: str, path: Path, media_type: str)` (frozen dataclass, call shape
:422-426); `RunOutcome(run_id, run_dir, outcome: Literal["settled","stopped"], stopped_reason: str | None,
spent_usd: Decimal)`; errors (all `ValueError` subclasses with a stable `code`): `RunDirExists`,
`AdapterRefused`, `ConfigMismatch`, `PathwayMismatch`, `BadSourceId`, `DuplicateSource`,
`SourceTooLarge`, `SourceUnreadable`, `UnsupportedMedia`, `CpDrNotBuilt`, `BadCap`. `LivePauseInForce`
is O5's class and is re-raised, not wrapped.

**`check_arguments(...) -> CheckedRun`** performs every check of the call shape (:441-459) **before any
write**, in this order; each has a RED test that also asserts `not run_dir.exists()`:
1. `run_dir`: `os.path.lexists(run_dir)` → `RunDirExists` (a dangling symlink also refuses, L10); its parent
   must exist and be a directory.
2. **Exact adapter type** (M3): `type(adapter) in (RecordedAdapter, LiveAdapter)` else `AdapterRefused`.
   `isinstance` is not used: a subclass that answers missing recordings by default, or a live-calling duck type
   reporting `ruling=None`, is refused. `adapter.config_id == model.config_id` (`ConfigMismatch`).
3. **Live gate read once** (M8): for an exact `LiveAdapter` take the `GateResult` (path, sha256, date) O5
   keeps on the adapter after `live_adapter` passed the gate (O5 plan :128; name re-derived at O5's tip).
   `run_pathway` does not call `check_live_gate` again (a second check against the default root could refuse
   a ruling the adapter accepted). `LivePauseInForce` therefore arises in `live_adapter`, before `run_pathway`;
   test: the real `docs/rulings/2026-10-31-context-plan.md` makes `live_adapter` raise, and a `LiveAdapter` built
   against a tmp ruling (via `rulings_root`; if O5's built `live_adapter` has no such hook, this test is reported as not built, never faked) yields `run.json` `ruling_*` equal to its `GateResult`.
4. `cap_usd` finite `Decimal` > 0 (`BadCap`; `NaN`, `0`, `-1` refused).
5. `case_id` and `run_id` match `Identifier` (`contracts.py:14`).
6. Context, then each source, are read by **`read_capped(path)`**: `os.open(path, O_RDONLY|O_NONBLOCK|O_CLOEXEC)`,
   `os.fstat(fd)` and `S_ISREG` on the fd (FIFO, directory, device → `SourceUnreadable`, never blocks; no
   stat-then-open gap, M6), then `read(MAX_BYTES + 1)` from that same fd (over → `SourceTooLarge`; same cap as
   `context.py:823-828`, `preparation.py:380`).
7. `load_context(raw)` (`ContextRefused` propagates); `context.run.pathway == pathway` (`PathwayMismatch`).
8. Sources: each `source_id` is an `Identifier`, not `context` (`CONTEXT_SOURCE_ID`, `context.py:33`), and
   unique **after `casefold()`** (`S1`/`s1` collide on case-insensitive APFS, M5: `DuplicateSource`);
   `media_type` is `text/html` or one of `SourceRequest`'s three types (`UnsupportedMedia`); `text/html` is
   converted now (pure), so `UndecodableHtml` and an over-cap converted text (> `MAX_BYTES`) refuse before any write.
9. `cp_dr=True` → `CpDrNotBuilt` (until O7b).
10. `preparation_request(context, run_id=…, context_path="context.json", sources=[…])` (`context.py:701-731`)
    is built now, so a bad run field (`ContextRefused`) refuses before any write.
`CheckedRun` holds the bytes read, the converted text, sha256s and the request.

**`stage_sources(checked, run_dir) -> None`**: `os.mkdir(run_dir)`; a `FileExistsError` here (lost race, M4) raises
`RunDirExists` and **nothing is written** (it never reaches the stopped path, which would write `run.json` into
another caller's directory). Then `sources/`, then the **bytes that were read and hashed**, never a second read:
`sources/<source_id>.txt` (text and converted HTML), `.pdf`, `.xlsx`, and `sources/context.json`. Each target
`resolve()`s under `sources/`; files are created with `O_CREAT|O_EXCL`. `prepare(request, run_dir/"sources",
run_dir/"pack")` is the only place the root appears (`preparation.py:369-377`). **After `prepare`** (L11) every
pack `Source.sha256` must equal the sha256 of the staged bytes for its id: `prepare` turns a vanished file into an
unreadable source (`preparation.py:389-390`), which would otherwise pass silently; a mismatch or a non-`ready`
source whose bytes were staged is a fault `prepare: source <id> changed`.

**RED tests (concrete).** Each refusal: valid arguments with one broken, assert the named error and
`not run_dir.exists()`: existing `run_dir`; dangling symlink at `run_dir`; `ScriptAdapter` object with `ruling=None`;
`class Sub(RecordedAdapter)` instance (exact-type refusal); `config_id` mismatch; `cap_usd` `Decimal("0")`, `Decimal("NaN")`;
context `pathway` ≠ `pathway`; `source_id` `"bad id"`, `"a/b"`, `"context"`, duplicate `"s1"`, and `"s1"` with `"S1"`; media
`text/csv`; sparse 50 MiB + 1 byte file → `SourceTooLarge` (spy: no read past cap+1); directory and FIFO as
sources → `SourceUnreadable` (the FIFO test must not hang: the test has a 5 s timeout); `\xe9` HTML without declaration →
`UndecodableHtml`; `cp_dr=True` → `CpDrNotBuilt`. Race: `os.mkdir` patched to raise `FileExistsError` → `RunDirExists`, no file
written under the path. Hash check: a staged file replaced between staging and `prepare` → fault, not a pack.
Positive: HTML + text + context stage to `sources/s1.txt`, `sources/s2.txt`, `sources/context.json`; `s1.txt` bytes equal
`convert_html(original).text.encode()`; the pack's source ids are `s1, s2, context`; the `context` source's media type is `text/plain` (`context.py:728`).

## Task 3: `run_pathway`, `_run_pathway`, `_finish_run`, `run.json` [ordering + money: mx-adversary]

**Files:** `src/deploy_workflow/run_pathway.py`, `tests/test_run_pathway.py`.

**Shape.** `run_pathway(...)` has exactly the contract signature (:435-438): `check_arguments`, `stage_sources`, then
`_run_pathway(checked, run_dir, adapter, prompt_for=_default_prompt_for)`. `prompt_for` is a **private parameter**, not
public (O5's `ToolLoop` takes `prompt_for`, O5 plan :169). `_default_prompt_for` composes with
`deploy_vii.live.prompts.build` for steps in `STEP_CONTRACTS` and raises a named `NoPrompt(step)` fault for the others; O6
replaces it. Not a stub: it is the real composer for the steps that have one and a refusal for those that do not.
`_run_pathway` does no adapter-type check (that lives in `check_arguments`), so Task 5's authoring harness can drive
it with a test adapter that never reaches `run_pathway`'s public path.

**Steps** (a named fault at or after step 2 goes to *Stop*):
1. `check_arguments` (Task 2): raises, writes nothing.
2. `stage_sources`, `prepare`, hash check (Task 2). `ValueError` from `prepare` → `stopped_reason="prepare: <redacted>"`.
3. `OwnerWorkflow.create(run_dir/"execution", pack, publication_directory=run_dir/"publication")`; `WorkflowError`
   → `workflow: <code>`. `run_pathway` never creates `execution/` or `publication/`.
4. O5 pieces: `Redactor` (regex only offline; O5's live path otherwise), `Budget(cap_usd, run_dir)`, `CallLog`, `ToolLoop(..., prompt_for)`.
5. **Loop over every step** (O5 Task 6 entry point; name re-derived at its tip). At the publisher's stop call
   `workflow.publish()` and continue; a `refused` publication is not a fault (O1 Q1). `StepStopped`, `BudgetExhausted`,
   `RunStopped`, `RecordingMissing` or `WorkflowError` ends the run as a fault (class name, redacted text); no receipt.
6. **`_finish_run(workflow, run_dir, …)`**: `write_receipt(run_dir/"owner-run.json")`, `verify_owner_run_receipt`,
   `render_owner_slice(execution, owner-run.json, publication-if-it-exists, run_dir/"delivery")`,
   `verify_owner_rendered_slice`, then `run.json`. `ValueError` from rendering or verifying (`owner_rendering.py:416-418`) is a
   fault `render: <code>`. After O1 a blocked walk (a `BLOCKED_EDGE` refusal or an unsettled head) is refused by
   `_outcome_rules` (`owner_rendering.py:662-665`), so it ends `stopped: render: owner_render_blocked` with
   `owner-run.json` kept (Q4). A verify failure after the rename keeps `delivery/` (`owner_rendering.py:960-961, 985`).
   `_finish_run` is also the unit tested on a one-module workflow (M2): `Run.requested_modules` defaults to the full preset
   (`contracts.py:92-95`) and `preparation_request` never sets it (`context.py:711-718`), so no one-module walk exists
   through `run_pathway`; the fixture is `tests/test_owner_workflow.py`'s `fw.make_pack` plus `publish`.
7. **`run.json` last**, written only by `_finish_run` and the Stop path, via a temp file in `run_dir`, `fsync`, `os.replace`.
   Fields (:400-407): `case_id`, `pathway`, `config_id`, `run_id`, `mode` (`live` iff exact `LiveAdapter`), `cap_usd`
   (Decimal string, O5's `money_text`), `sources` [{`source_id`, `path`, `sha256` (original bytes), `media_type`
   (caller's), `converted_sha256` or `null`}] plus the `context` entry (`media_type: "text/plain"`, Q5),
   `cp_dr_invoked` false, `replayed_from_run` null, `outcome`, `stopped_reason`; live only `ruling_path`, `ruling_sha256`,
   `ruling_date` from the adapter's `GateResult`. The offline key set is pinned in a test.
8. `RunOutcome(...)`; `spent_usd` = budget spent (settled plus held unknown). Offline usage is test-authored: cap
   logic, not money (`mode: offline`).

**Stopped runs** hold `sources/`, `pack/`, `execution/`, `calls.jsonl`, `raw/`, `run.json`, and, per the Q4 amendment,
`publication/` after a publish, `owner-run.json` after the walk, `delivery/` after a post-rename verify failure.

**RED tests** (fast, no CP-1 promotion):
- Refusals through `run_pathway` leave no directory.
- First request `RecordingMissing` (empty recordings dir): `stopped`, reason starts `RecordingMissing`, one `calls.jsonl` record
  `error_class == "RecordingMissing"` with `"0"/"0"/computed`, tree is the stopped set, `NoPrompt` is not hit (the test patches `prompt_for`).
- `NoPrompt`: a step without a composer → `stopped`, reason `NoPrompt: <step>`.
- Budget: `cap_usd=Decimal("0.0000001")` → first request not sent, `BudgetExhausted`, `spent_usd == Decimal("0")`.
- `_finish_run` on the one-module fixture: files `owner-run.json`, `delivery/report.html`, `run.json` exist, `run.json` is the last
  file written (write spy), key set pinned; with `render_owner_slice` patched to raise `ValueError("owner_render_blocked")` →

- Unexpected exception (`prepare` patched to raise `RuntimeError`) propagates; `run.json` absent.
- Second call with the same `run_dir` → `RunDirExists`, first run's tree hash unchanged. No network (O5's transport trap).

## Task 4: Commission the synthetic oracle `cases/o2-synthetic/` (H1) [oracle roles, no builder code]

Frozen oracles cannot drive a `prepare`d pack, and a rebase would hide that: `preparation_request` appends a `context` source
(`context.py:726-729`); CP-0 `validate_review` requires every prepared source assessed once (`readiness.py:341-344`) and no
frozen oracle has a `context` row; every oracle cites `page:` locators over supplied page text hashed as pages joined with `\f`
(`tests/cp3_cp6_runs.py:87`), whereas `prepare` makes `line:N` spans over file bytes; `cases/context/research-minimal.json`'s run
fields differ from the oracle run. A rebase would derive the locator from the quote, so a wrong-page or deliberate gap-case
citation would pass. **Dropped.** A new oracle is commissioned under B2 (AGENTS.md independence rule): the preparer, the
reviewer and the O2 builder are three different agents, and the ids go in the ledger. The controller dispatches both roles.

**Preset.** The one preset O1 Task 5's end-state table shows settling through CP-5 on frozen submissions (expected
`portfolio_decision`); the controller names it in the brief after reading that table.

**Preparer (an agent that is not O2's builder or reviewer).**
Inputs: the chosen preset's frozen oracles (`cases/*/submissions.json`, `manifest.json`, `expected.json`, pinned in
`cases/PINS.json`), `cases/context/research-minimal.json` for the file shape, `load_context`, `preparation_request`, `prepare`,
`text_content`. Writes, all under `cases/o2-synthetic/`:
1. One `.txt` per source: the existing synthetic page text of each source, pages joined with `"\n"` (each page break a line);
   no text is invented.
2. `context.json`: the run fields of the S1 / CP-5 base run (`cases/cp3-cp6-owner/manifest.json` R3: issuer `northbridge-synthetic`, as_of 2026-01-10, `case_kind` synthetic) with the preset's
   pathway, loading under `load_context`. A module whose oracle was frozen on different run fields (CP-8: `cases/cp8-owner/manifest.json`, as_of 2026-04-30) is reported as an oracle gap and dropped from the case, never re-dated.
3. A `run_id` and a pack built **once by `prepare`** (the same call `run_pathway` makes); its source hashes and line numbers are the
   ones every citation is cut to.
4. `submissions.json`: every module submission of the preset re-cut by hand/by a script to those `line:N` locators and file
   hashes, plus the CP-0 row for `context` (an assessment of the context file as a source, with its own cited line). No value,
   id, status or number differs from the source oracle except locators, hashes, and that one added row.
5. `manifest.json` (source files, sha256 each, `run_id`, how each submission maps to the source oracle's) and an entry in
   `cases/PINS.json`-style pins so a drifted file fails.

**Reviewer (`mx-precise`, independent of the preparer and the builder).** Checks, with saved probe scripts:
(a) each citation's quote sits on its cited line of the **prepared** pack (script: prepare the pack, look up `line:N`);
(b) every gap or absence case of the source oracle (missing source, `gap=True` case, absent figure, unsupported claim) stays a
gap, with the same status and no new citation; (c) a field-by-field diff of every submission against its source oracle shows only
