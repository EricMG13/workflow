## Contract and source trace

1. **Actual source authority.** Registry CP4 has exactly legal_covenants and
   declares that step pack-source capable. live.context.SOURCE_SCOPES calls
   cp4_legal.upstream_of(...).legal_sources; cp4_upstream selects pack-order ready
   source IDs whose authenticated current CP0 T3 authority is executed/filed.
   Explicit declared/readable intersection and prior registry check prevent the
   all-pack fallback from becoming permission. Empty legal scope refuses. The
   exact cases expose only legal-covenants; raw identity/financial/private IDs,
   source-free owners and CP4 extract_statements stay denied. Legal text itself
   remains genuine source text, not censored or converted to a calculated result.

2. **Canonical CP1 authentication is complete.** model_interface appends pack and
   financial-review; canonical_tables appends downstream-report and
   statement-history; promote_cp1 prefixes scheduler Attempt.inputs. The frozen
   four-tail order and exact tuple/hash/status equality are correct. A stub that
   accepts only scheduler inputs or arbitrary trailing strings cannot satisfy
   the contract. Matching Run/hash/status alone also cannot pass: exact retained
   five-stage validation, public cp1_registers, QualityReview/cp1_quality_inputs/
   assess_quality, CP1Handoff and promote_cp1 candidate/settlement/head equality
   are required. Public validation supplies the actual financial/calculation
   semantics; host adds no math, QA threshold, Model publication or old receipt.

3. **The public pure seam exists.** validate_cp1_stage rederives the first four
   source/financial/narrative/readiness prefixes; cp1_registers rechecks all four;
   promote_cp1 rederives quality/candidate through its public callback and calls
   finish with PROMOTED. A read-only facade can expose the retained attempt as
   the corresponding pending historical validation state without changing the
   real store. Envelope/write_envelope/envelope_issues/read_envelope operate on
   strings; no file export is needed. Candidate, handoff and settled-result hashes
   are distinct identities. Exact handoff envelope/sidecar and full head fields
   (including inputs/commands/notes/qualification) are required, preventing an
   authentic tail from licensing changed facts/claims/limits.

4. **Blocked CP1 has an exact preserved degradation.** Existing cp4_upstream
   accepts actual blocked CP1 but offers no figures/facilities and carries its
   blocking limitations; the restricted edge still allows raw legal inspection.
   The oracle requires real repair1/rejected predecessor0, matching scheduler
   inputs, retained invalid step/raw payload/optional output, rederived public
   validation and existing bounded_issues normalization, pure empty-candidate
   settlement and exact blocked head with null qualification. Thus it neither
   adds a promoted-only gate nor accepts a fake blocked status/copied financial
   data. A callback that merely trusts stored issue strings is explicitly barred.

5. **Zero-write verification is a contract invariant.** Ordinary Execution
   constructor/read/pack/blob access are read-only; its mutating methods acquire
   locks/write snapshots. The local facade must forbid those real paths and
   capture only the exact expected public candidate/validator or invalid-quality
   callback against authenticated retained inputs. Its finish/submit override
   cannot execute arbitrary callbacks or append state. Future tests must observe
   zero files/blobs/snapshots/current changes and zero writer-lock entry across
   factory/invoke/bind, including refusal. This requirement is implementable in
   host.py; no shared API/file or hidden envelope exporter is missing. Its future
   implementation is not established by this static review.

6. **Currentness and precedence stay explicit.** Factory first authenticates the
   actual executable ticket/ordered retained prefix, exact global pending/input

   snapshot. Genuine CP0 scheduler refusal creates no workaround ticket. Invoke
   JSON validation precedes lock/currentness, then dispatch/argument checks; stale

   a new legitimate snapshot makes an old session stale_binding. Revalidation
