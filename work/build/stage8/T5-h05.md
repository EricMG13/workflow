## The defect
`host.py` `invoke` (about :1046) advances `self._sequence` and then calls `_json_arguments`.
- A lone surrogate in a value or a key passes `_json_arguments`, because it is a `str`.
- A 210-deep frame also passes it, and later fails inside the owner or financial layer (`owner_workflow.py:~1189`, `financial_workflow.py:~726`: `_parse`, `model_dump`, `_retain`).

Either way the owner's `_epoch_calls` never records the call, so every later call fails `call.sequence != len(self._epoch_calls) + 1` with `identity_mismatch`.

## The fix direction (Codex)
Validate in `_json_arguments`, so the frame is refused as `bad_arguments` with a receipt that every layer can serialise and retain.
- Check that `json.dumps(arguments, ensure_ascii=False).encode("utf-8")` succeeds. A surrogate in a key or a value raises `UnicodeEncodeError`, which is a `ValueError`.
- Add a depth bound, as a named constant, at or below the depth the owner and financial layers can round-trip.
  - Find that depth from the code: the limit pydantic-core applies when `_parse` validates. State the number and where it comes from in a comment.
  - The 210-deep frame must be refused.
- Do not skip or reorder the sequence check, and do not make the owner layer tolerate a gap.
- Keep the `bad_arguments` receipt's `arguments` as `{}`, as it is today.
